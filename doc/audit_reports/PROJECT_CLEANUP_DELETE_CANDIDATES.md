## 2. Technical Justification for Selected Actions

### 2.1 Why `gpio_data_121_to_130.vcd` (4.67 GB) Can Be Safely Removed
- **Redundancy:** The simulation run generated two waveform representations:
  1. `gpio_data_121_to_130.fsdb` (809 KB binary FSDB): Contains all 121,424 variables, multidimensional arrays, packed/unpacked structures, and virtual interface probes with fast indexed access.
  2. `gpio_data_121_to_130.vcd` (4.67 GB ASCII VCD): Text dump of the exact same signal transitions, missing MDAs and structs.
- **Tool Compatibility:** Synopsys Verdi natively uses FSDB (`-ssf gpio_data_121_to_130.fsdb`). Verdi does not use or require the 4.67 GB VCD file.
- **Regeneratability:** If an ASCII VCD is ever required for an external tool (e.g., GTKWave), it can be instantaneously regenerated directly from the FSDB file using Synopsys `fsdb2vcd gpio_data_121_to_130.fsdb -o output.vcd` without resimulating.
- **Safety:** Removing this file instantly frees **4.67 GB** of disk space without impacting any testbench, verification log, or Verdi session.

### 2.2 Why `gpio_data_121_to_130.fsdb.bak` (242 KB) Can Be Safely Removed
- This file was a temporary backup copy made before recompiling with `-kdb` and full dump options. It contains only 47,516 variables and lacks internal DUT logic. The active `gpio_data_121_to_130.fsdb` (809 KB) contains the complete 121,424 variable dump and is fully verified.

### 2.3 Why `ucli.key` (0 bytes) Can Be Safely Removed
- These zero-byte files are generated automatically whenever VCS exits. They contain no user data, scripts, or configuration, and are automatically recreated by VCS on demand.

### 2.4 Why Older Simulation Binaries & Logs Are Safely Archived
- Moving `simv_uvm`, `compile_uvm.log`, and `sim_uvm_waveform.log` into `cleanup_archive/` isolates them from the current active verification workspace (`tb/uvm_soc/`) while guaranteeing that if historical comparison is ever desired, the files remain accessible.
